## How the agents work (decided)
- **Claude Code CLI** (`claude -p`, existing Claude subscription, no API key) for the heavy work; each agent follows `Agents/Shared Agents/AGENTS.md` and its own file.
- **Apple Foundation Models** (on-device, free, offline) for light work: course detection on Unsorted items, the Manager's routing when the keyword rules are unsure, and junk triage.
- **The Manager** decides the agent (when asked to) and the effort for everything except a question typed straight into an agent's own chat, where you keep your choice of agent and the Manager only sets the effort. Tiers: **quick** (haiku, low: short single lookups starting what/which/when/list/any/how many/is/are), **standard** (Sonnet, medium: explaining, planning, write-ups, filing) and **deep** (Opus, high: Writer). The model is always passed explicitly, because a resumed Claude session otherwise keeps the model it last ran on. Settings → Agents: the Manager's switch (off puts every run back on Claude Code's defaults), a ceiling on the tier, and a 7-day count of runs by tier.
- **Safety:** chat is read-only. Moving or renaming files shows a plan and waits for Approve; the app does the move (copy → verify → original to `.trash`). Agents never delete. Writer coaches and never writes the submission.

## Built 2026-10-02: the Manager-centred model

**The model.** The Manager is the only agent that looks for work, and everything goes through it. For each job it picks a **helper** and the relevant **course agent(s)** to consult first; the helper does the job; the Manager reviews the result and undoes it if it fails. **Helpers never ask for approval and never start anything themselves; course agents only advise.** Direct chat with any agent stays for questions. The plan-then-tick flow is gone: no waiting-for-your-tick bubbles, no "Act without asking" or "Reversible jobs" settings, no approve-streak offers, no always-asks rule for Writer. Sort Now, File Now and the note-page buttons run straight through the same pipeline and show live progress and an Undo (`JobProgress.swift`).

**The pipeline** (`ManagerScan.swift`, `ManagerReview.swift`): consult (a course agent on Haiku reads its `Course briefing.md` and advises the helper) → work (one call, scoped write permissions) → review → done, or one retry with feedback, or undone and logged. Job states: planning, consulting, working, checking, done, rejected, failed. Old waiting plans in `inbox.json` are expired on load. The review runs on this Mac: only the permitted note changed (nothing in `Agents/` or `Templates/`), frontmatter and headings intact, **sections a job may not change are word-for-word the same, and every line of Oscar's own (anything not in the template) is still there**, new notes have every template key and the right `base`, name and course, research findings have links and every link opens, nothing that reads like instructions aimed at an AI, the Analyst's answers agree with a second independent solution to within 1%, and Apple's on-device model checks Writer's sections read as a plan and not finished prose. Tested without spending usage against a stand-in for Claude on a throwaway vault (`PipelineCheck.swift`, part of `--check`): success, a problem fixed on the retry, rejection with undo, nothing to do, the loop breaker, and the checks. That test found two real bugs, both fixed: a job's note claim was released during the review, and undo restored the wrong version.

**Models.** The Manager runs only on your Mac (rules, plain code, Apple's on-device model; no Claude), including the morning brief (written from plain facts) and the Monday week-ahead per course. Sorter, Scribe, Librarian, Planner, Tutor, Researcher on Sonnet (medium); Writer on Opus (high); **Analyst on Sonnet (high), run twice and compared**; course agents on Haiku (low) when consulted. New effort tier "careful" for the Analyst. If Apple Intelligence is off, the Manager falls back to rules and code checks.
