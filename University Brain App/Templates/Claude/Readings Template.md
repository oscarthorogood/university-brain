## How to organise Reading notes

- **How the app shows links:** the note page's **Related** card lists every Revision, Research, Zotero, Resources or OneDrive item this note links to (through `resources`, `onedrive`, or any `[[link]]` in the text) or that links back to it. **Links to** lists the other Items notes it links to (through `related`, `readings` or any `[[link]]`). Properties (course, date, status, tags) are edited on the page. Link things once, with a wikilink; don't repeat them by hand.
- One note per reading (article, chapter, paper), filed in the top-level `Readings` folder — not nested under the course folder.
- Always link `course:: [[Course Name]]` so the reading is grouped correctly in course views; set `type` to `Course Reading` (set by the course) or `Research Source` (found yourself).
- Fill in `authors`, `date`, `item type`, `full citation`, and `in text citation` at the time of adding the note — doing this immediately avoids having to hunt down citation details later when writing an essay.
- Use `url` to link the source (or the `Resources` PDF location if not web-based) rather than pasting the full text into the note.
- Keep `summary` to a few lines capturing the key argument or findings, so readings are scannable without reopening the source.
- Use `related` to connect readings that discuss the same theme or respond to each other.

**Pulling detail from attachments**
- Verify the citation against the PDF's title and imprint pages. Filenames and old Notion titles are unreliable (see `Agents/Shared Agents/open-items.md`).
- Build **Structure** from the table of contents or headings, then read the parts set for the course in full.
- Put a page number on every key point, finding, definition and quote so it can be cited later without reopening the file.
- For long textbooks, cover only the chapters set, and say which ones in **Source details**.
