## How to organise Course notes

- One note per course, created once at the start of the semester (or term) and never duplicated.
- Lives at the top level of the `Courses` folder — do not nest course notes inside subfolders, since every other note type (Lecture, Reading, Essay, Project, Revision) links back up to it via the `course` field rather than by folder location.
- Everything else (lectures, readings, essays, projects, revision notes) belongs in its own top-level folder and links back to this note through `course:: [[Course Name]]` — it should never be filed underneath the course note itself.
- Fill in `year` (`One` / `Two` / `Three`) and `semester` as soon as the note is created so the course can be filtered and grouped correctly in Bases views.
- Update `status` as the course progresses (`In Progress` → `Done`), and keep `summary` as a one- or two-line description of what the course covers.
- Use `related` to link sibling or prerequisite courses, not individual lectures/readings — those are already captured automatically via Linked mentions.

**Pulling detail from attachments**
- The course handbook and first-lecture slides usually hold everything for **Course details**, **Learning outcomes**, **Assessment** and **Weekly schedule** — read them in full when the course starts.
- Every deadline found in any attachment (briefs, slides, emails) goes into **Key dates** and onto the `due` of its Essay/Project note.
- Cite the file and page for each detail. Leave blanks rather than guess.
