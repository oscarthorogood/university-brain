## How to organise Tutorial notes

- **How the app shows links:** the note page's **Related** card lists every Revision, Research, Zotero, Resources or OneDrive item this note links to (through `resources`, `onedrive`, or any `[[link]]` in the text) or that links back to it. **Links to** lists the other Items notes it links to (through `related`, `readings` or any `[[link]]`). Properties (course, date, status, tags) are edited on the page. Link things once, with a wikilink; don't repeat them by hand.
- One note per tutorial (or seminar), filed in the top-level `Tutorials` folder — not nested under the course note.
- Always link `course:: [[Course Name]]` so the tutorial is grouped correctly in course-grouped Bases views and appears under the course's Linked mentions.
- Fill in `Tutorial No.` so tutorials sort in delivery order within a course, even if notes are created out of order.
- Lead with **My work** — the exercises or problem sets you actually completed before or after the session — since that's the most valuable record for revision later. Tutorial notes are secondary, capturing what was covered/corrected in the session itself.
- Link any sheets, solutions, datasets or handouts via `resources`, and any related readings via `readings`, rather than pasting content inline.
- Use `related` for links to the lecture(s) this tutorial follows up on, or other tutorials it builds on.
- Keep `summary` to a one-line topic description so a course's tutorial list is scannable at a glance.

**Pulling detail from attachments**
- Copy the questions from the tutorial sheet verbatim into **The task**, with question numbers and marks.
- If a solutions file is linked, fill **Solutions check** from it — never overwrite your own answers with the model ones.
- For data files (`.xlsx`, `.csv`, `.dta`), note the file, sheet and variables used next to the question they belong to.
- Cite a location for every extracted point (`Q3`, `p. 2`, `Sheet "Data"`). Leave blanks rather than guess.
